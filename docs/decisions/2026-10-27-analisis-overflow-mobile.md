# Runner de tests nativo de Node (sin dependencias nuevas)
- Contexto: `main` no tenía test runner. Para arreglar el desborde horizontal de `/analytics` en mobile hacían falta tests automáticos de los componentes (`BarRow`, `TrendDual`, `SpendHeatmap`, rango, página) sin sumar costo ni dependencias pesadas como vitest, jest o Playwright (la spec, en P2, descartó E2E).
- Decisión: se usa `node --test` con el hook de carga `tests/setup/ts-loader.mjs` (registrado en `tests/setup/register.mjs`). El hook transpila `.ts/.tsx` con el `typescript` que ya está en devDependencies (JSX a `react/jsx-runtime`) y resuelve el alias `@/` a `src/`. Se corre con el script `npm test` y los tests viven en `tests/**/*.test.mjs`. También se sumó `src/lib/tooltip-position.ts` (`clampTooltipLeft`), un helper puro para poder testear el tooltip del heatmap.
- Consecuencias: los tests nuevos tienen que ser `.mjs` y renderizar con SSR (`react-dom/server`), porque no hay DOM ni layout real. Las verificaciones de ancho y scroll siguen siendo manuales o con DevTools. El loader solo transpila (no chequea tipos, para eso está `tsc --noEmit`) y no entiende otros alias ni imports de CSS: si un componente los usa, hay que extender el loader. Si más adelante se adopta vitest o Playwright, `tests/` se puede migrar sin tocar `src/`.
